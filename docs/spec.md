## 2. Alias search model

**Index (read-only, never written by Burrow).**
- An alias block is any block on a page whose string matches `^(Keyword)::` case-insensitively. Keyword is a Burrow setting (default `Aliases`), and Svy sets it to the same value as roam-aliases. The case-insensitive match also picks up `aliases:: EMP`.
- Values come from `split(",")`, then `trim()`, with surrounding `[[ ]]` and `#` removed. Empty values are dropped.
- The page is the identity. One alias can point to several pages, and Burrow then shows every page and guesses none (Thymer rule).
- Built once at idle after load: titles (6,904, 57 ms query) plus aliases. Refreshed by a pull watch on the `Aliases` page's `:block/_refs` and a 60 s TTL checked when a popup opens, never on a keystroke.
- **Burrow never edits `Aliases::` blocks** unless the user turns on one of the two alias-write switches (BRW-6, §13, both off by default). The template rule says roam-aliases owns that comma list; with the switches off, Thymer's ⌥A "create alias while picking" stays unported.

**`[[` behaviour.** An alias hit renders as one Burrow row: `alias ↳ Page Title`, matched span in `.rm-search-match` weight. If native results already show the page by title, Burrow adds no row for it.
- Commit inserts `[alias]([[Page Title]])`, the same text roam-aliases writes, so both plugins leave identical source. The setting `Alias link format` offers `[alias]([[Page]])` (default) or `[[Page]]`.
- **With roam-aliases present** (`.rm-aliases` found inside the native popup): Burrow does not draw its own alias rows, because roam-aliases already lists them. Burrow still uses aliases for ranking and for `((` expansion. Two plugins listing the same alias would be the "fight" the decision forbids.

**`((` behaviour.** No new row type. An alias hit acts as query expansion: if the query, or a run of its tokens, matches an alias of page P, blocks that reference P get the alias boost (§3). Typing `Mike Khieu` in `((` then finds blocks that mention `[[Entities/Michael Khieu]]`. Burrow never inserts a page link from `((`.

## 3. `((` ranking

Roam's results stay as they are. Burrow adds a short ranked strip above them (§4).

**Candidate pool = referenced blocks only.** In notes that is 3,767 blocks: `[?r :block/refs ?b] [?b :block/string]`. Without the `:block/string` clause the count is 7,269, because it also counts referenced pages, which `((` does not want. The query takes 61–200 ms. Burrow builds the set once at idle and refreshes it lazily when a popup opens if it is older than 60 s. Native search already covers unreferenced blocks. Restricting Burrow to the referenced set keeps every keystroke a JS loop over about 4k strings, with no datalog.

**Order inside the strip:**
1. Match tier from the Thymer scorer: strict before close (typo).
2. **Originals before quoters.** A block whose text only contains `((X))` folds into X, and X takes its place. The original block, the one others already reference, ranks first.
3. Inbound ref count, as `log2(1+refs)` steps.
4. Alias boost (§2), current-page boost (+small), pick memory (phase 2).
5. Shorter text, then uid, so ties always break the same way.

Before matching, the key strips Roam markup (`[[ ]]`, `(( ))`, `{{ }}`, `**`, `^^`, attribute prefix) and uses Thymer's spaced and compact forms, so `ant man` = `Ant-Man` and `real time pcr` = `Real-time PCR`. Matching is on word boundaries. A rough substring probe for `ant` + `man` over the referenced set alone gave 66 hits (`important`, `semantic`…). Plain `ant` matches 460 referenced blocks and 15,780 blocks in the whole graph. The strict tiers rule those out.

**Strip size:** at most 3 rows. A row is dropped when native's first row is already the same block. Native rows carry no uid, so the check compares rendered text; if that is ambiguous, the row stays.

**Default selection.** The decision says the referenced original shows *first*. With the `((` ranking toggle on and Burrow's top row being a referenced original that native has not put first, that row is **pre-selected**, so Enter inserts it. Native's own active-row highlight is muted while Burrow owns selection. ↓ past Burrow's last row hands selection back to native's first row.

**Acceptance:** svy: `((ant man` → first, pre-selected row is `((3XSu0IJ8f))`. notes: `((real time pcr` → `((6ZtlGN-Np))`. svy (BRW-10, §17): `((black pan` → first, pre-selected row is `((cs1PFq5go))`, and no code block among the rows.

## 4. Popup hook

**Native DOM, from Roam's live stylesheet** (the class names in the compiled bundle are generated, so the CSS is the stable contract):
`.rm-autocomplete__results` (popover, 400 px, max-height 300 px, flex column) › `.rm-autocomplete__results-main` › `.rm-autocomplete__results-scroll` › `.rm-autocomplete-result` rows (with `.rm-autocomplete__ref-count`, `.rm-search-match`); `.rm-autocomplete__preview` › `.rm-autocomplete__preview-content` (title, `__preview-title__refs`, `.rm-zoom` breadcrumbs, ghost blocks); `--expanded` / `--expanded-left` when the preview is open; `.rm-autocomplete-footer` with `__action--preview` and hotkey icons. The Ctrl-Shift-9 Advanced Block Search dialog is `.rm-search-path`.

**Open questions that need one live capture before code** (phase 1, step 0, §8): the active-row class, whether native rows are React-keyed children of `-scroll`, and what closes the popup after a programmatic value change.

**Detection, with no global MutationObserver.** A capture-phase `input` / `keydown` handler on `textarea.rm-block-input` scans the text before the caret for the last unclosed `[[` or `((`, the same way inline-autocomplete's `insideRoamSyntax` does. Only then does it run one `querySelector('.rm-autocomplete__results')`. While a popup is open, one `ResizeObserver` follows it, and it is dropped when the popup closes.

**Burrow's own DOM.** One portal node on `document.body`, sitting flush against the native popover's edge (above it, or below when there is no room), the same width, built from Blueprint `bp3-menu` / `bp3-menu-item` tokens.
- It never gets the class `rm-autocomplete__results`: roam-aliases (`querySelector(TARGET_CLASS)`) and inline-autocomplete (`roamAutocompleteVisible`) both key on it.
- It never inserts into or reorders React-owned native nodes. The one native mutation is a reversible class `burrow-owns-selection` on the native popover, which mutes the native active-row style while Burrow holds selection.

**Keyboard ownership state machine** (explicit and reversible):

| State | Enter | Leave | Keys Burrow consumes |
|---|---|---|---|
| IDLE | — | popup opens with a Burrow feature enabled | none |
| ARMED | strip has rows, native holds selection | → OWNED on ↑ from the strip edge or on pre-select (§3); → IDLE when the popup closes | none |
| OWNED | a Burrow row is active | ↓ past the last row → ARMED; Esc → ARMED and Esc passes through to Roam; caret move, blur, popup close or composition start → IDLE | ↑ ↓ Enter Tab |

Every handler first checks `e.isComposing`, `state.composing`, that the event target is the tracked textarea, and that the selection is collapsed. If any check fails, the event passes through untouched.

**Commit, byte-for-byte.** On keydown, Burrow snapshots `{uid, value, selStart, selEnd, token:{kind,start,end,query}}`. A write happens only when:
- `value.slice(start, caret) === open + query`,
- the auto-inserted closer, if any, sits right after the caret,
- the caret has not moved, and
- the uid is still focused (`ui.getFocusedBlock`).

`next = value.slice(0,start) + insertion + value.slice(closerEnd)`. That is one `nativeSetValue` plus one `input` event, `ignoreNextInput`, and the caret set to the end of the insertion in the next rAF. Then a post-check: `ta.value === next`. If it does not match, Burrow logs `__BURROW.lastFailure` and **never writes a second time**. A precondition failure returns `false` and the key reaches Roam as if Burrow were absent.
- Burrow never calls `updateBlock` (roam-aliases does). Writing through the textarea keeps Roam's undo stack and avoids a re-render race.
- **Only the token span changes.** Every byte outside `[start, closerEnd)` must be identical.

**Byte-for-byte gate (run on notes, page `Burrow/Fixtures`).** For each case, pull `:block/string` before and after: Enter, Tab, Esc, ↑, ↓, ←, →, typing `abc`, Backspace, an IME composition (Pinyin), click-away, and failure recovery (caret moved between keydown and commit; scorer throws; extension unloaded mid-popup). Expected: the string is unchanged in every case except a Burrow commit, where only the token span differs. Run the same sequence once more with every Burrow toggle off. Its result must equal the run with Burrow uninstalled.

**Theme:** `.bp3-dark` on body or an ancestor first, then the measured `body` background luminance (notes measured `rgb(32,43,51)`, dark). Never `prefers-color-scheme` alone. Re-measure on class change of `<html>` / `<body>` only. Colors come from Roam's own tokens: no badges, no pills, plain `refs` number in `.rm-autocomplete__ref-count` style.

## 5. Drill-down: `title#heading > child`

**Grammar (inside `[[ ]]` only):** `expr := title ( "#" q )? ( ">" q )*`
- `title` resolves to the best page by title or alias with the Burrow scorer. **Drill mode switches on only when `title` resolves exactly** (title or alias, case- and separator-insensitive). Titles that legitimately contain `#` or `>` (`C#`, `a > b`) stay native, because the full string then matches a page and nothing parses.
- `#q` matches headings (`:block/heading` 1–3) anywhere under the page. notes has 4,130 heading blocks; `Systems/Executor Lanes and LaunchAgents` has 36. An empty `#` highlights the first heading.
- `> q` matches the **direct children** of the current target, one level, as in the Slack post. An empty `q` highlights the first child. `title > q` without `#` starts from the page's top level.
- Each step picks the best scorer match. Ties go to outline order. To get another sibling, the user types more. There are no arrow keys in the preview, per the brief and the Slack post.

**Preview.** While drill mode is on, Burrow owns the native preview area's *content*: it hides `.rm-autocomplete__preview-content` with a class and renders its own read-only outline in a portal laid exactly over it, so there is one pane, not two.
- The outline shows a breadcrumb trail of page › heading › … › parent (parent context stays visible), the resolved node's siblings, and the resolved node's first 2 levels of children.
- **The resolved block gets a highlight** (Roam's block-highlight color from the theme, no outline box), and `scrollIntoView({block:"nearest"})` runs on each change.
- The outline is built from one `pull` of the page tree, cached per page uid until the popup closes. It renders as text: `pointer-events:none` on bodies, no `renderBlock`, so a click cannot open an editor and change source.

**Commit.**
- Enter or Tab with a drill expression replaces the whole `[[expr]]` token with `((uid))` of the resolved block.
- If nothing below the page resolved, the commit is `[[Page Title]]`.
- **Burrow never lets Enter create a page named `title#heading > xxx`.**
- Esc leaves the text as typed and passes through.

**Example on notes (each step checked read-only over CDP):** `[[Systems/Executor Lanes and LaunchAgents#grok lane > never`
- `Systems/Executor Lanes and LaunchAgents` is an exact page title.
- `#grok lane` resolves to the level-2 heading `((TsuLMBRGP))` "Grok lane (since [[October 17th, 2026]])".
- `> never` matches one of its 6 direct children: `((-EeRGLF5U))` "Never Grok for: document writing …".
- The preview shows the trail `Systems/Executor Lanes and LaunchAgents › Grok lane …` with that child highlighted. Enter inserts `((-EeRGLF5U))`.

**Counter-example:** `[[Executor Lanes#grok lane` does **not** enter drill mode. `Executor Lanes` is not an exact title: the pages are `Concepts/Executor Lanes` and `Systems/Executor Lanes and LaunchAgents`, and neither has an alias. The text stays native. A namespaced page needs its full title or an `Aliases::` entry to start a drill.

## 6. Per-keystroke cost budget

**Measured on notes** (103,156 blocks, 6,904 pages; Roam Desktop, read-only):

| Operation | Cost | When Burrow runs it |
|---|---|---|
| datalog regex scan of all blocks | **110 ms** | never per key |
| referenced-block set + ref counts | 61–203 ms | idle once, then lazy ≥60 s |
| key normalisation of 3,767 refd blocks | 71 ms | idle once, with the set |
| title list | 22–57 ms | idle once + watch |
| JS match over 3,767 refd keys | **0.9–2.9 ms** | per key in `((` |
| JS match over 6,904 title keys | **1.9 ms** | per key in `[[` |

**Budget (each is a release gate, measured with `performance.now()` marks exposed at `window.__BURROW_PERF`):**
- **0 datalog queries and 0 `pull`s per keystroke.** The exception is the first `#` or `>` after a title resolves: one `pull` of that page tree, then cached.
- **Burrow JS ≤ 4 ms p95 per input event** on notes (match, rank, diff-render of at most 3 rows plus preview). Layout is read only in a frame callback (§14). No full `innerHTML` rebuild when rows are unchanged; the active-row change touches classes only (inline-autocomplete's `render` / `setActive` split).
- **Input→paint delta vs Burrow-off ≤ +5 ms p95** over a 200-keystroke scripted run with the popup open, on a `Burrow/Fixtures` block. Baseline first, then Burrow on, n ≥ 2 runs each, with the spread reported.
- Idle builds go through `requestIdleCallback` chunks of ≤ 6 ms (Thymer's cooperative lane) and pause while a popup is open.
- Kill switch: every feature toggle is checked at the top of the handler; all off = listeners are present but return in the first line. Command palette `Burrow: Disable all` for safe mode.

## 10. Phase 1 build notes (BRW-2)

Findings from the live capture (§8 step 0) that the code relies on:

- Native rows are `.rm-autocomplete__results-scroll > div.dont-unfocus-block[title]`; the `title` attribute holds the page title or the block text. The active row has **no class**: Roam paints it with an inline `background-color`. Burrow detects it that way and mutes it with `!important` only while the popover carries `burrow-owns-selection`.
- In `((` Roam's first two rows are "Create as footnote" and "Create as block below", and the second is active by default, so Enter on native creates a block. Pre-select moves Enter to Burrow's original.
- The popover is a direct child of `<body>`, popper-positioned, `box-sizing: border-box`, `max-height: 300px`. roam-aliases prepends `.rm-aliases` (and adds `alias-container`) inside it.
- A programmatic `value` set plus one `input` event, with the caret set in the next frame, closes Roam's popup and saves exactly the new string (checked: `x ((6ZtlGN-Np)) ok`).
- Escape with the popup open closes it and leaves the editor.
- **Strip placement.** The strip is a portal on `<body>` laid over the top of the popover. A reversible class `burrow-pad-N` on the popover adds `padding-top` for N rows, so no native row is covered and the strip reads as the popover's first section. No node is inserted into Roam's tree.
- **Ranking bands.** Exact and word-boundary substring matches share one band so inbound refs decide between them; token-wise matches come next, recall (abbreviation, initialism, typo) after, close matches last. Substring hits must start at a word boundary, also in the separator-free form, so `ant man` does not hit `important manual`.
- **Roam swaps the popover element** on native arrow navigation. A disconnected popover only means "closed" when no replacement exists; otherwise Burrow re-attaches.
- **Strip admission** is stricter than Thymer's picker, because the strip pre-selects and Enter takes it. Admitted: whole-key, prefix and word-boundary substring matches (also separator-free); exact-word matches in or out of order; initialisms. Left to Roam's rows: prefix-only words in any order (Thymer's 440 tier: on notes `ant man` → "antibiotics … management"), close matches (a word missing), and recall matches with no exact word. Alias rows keep the full forgiving scorer (a one-word typo like `lorinatr` → `lorinator`), since aliases are few and short.
- **Per-key cost.** A strict pass behind a cheap prefilter (the separator-free key must hold each clause's longest word, or its initials start the query), with the passing set cached per needle set: typing forward scans the cached superset, Backspace hits the cache. Recall runs only when the strip is not full, never for one-word queries, and only over blocks found through a word index (an admitted recall row needs one exact word). - **Test harness trap** (Roam, not Burrow): after Escape Roam leaves the block *selected*, and that selection survives a programmatic `setBlockFocusAndSelection`. - **Indexes** are built with `data.async.fast.q` where Roam offers it. svy: 5,304 referenced blocks, 200 ms query; notes: 3,767, 172 ms. Alias pages are found by exact title lookups for the keyword's spellings, then their referring blocks.

## 18. Recent rows and frequent first (BRW-14)

Two switches, both on: `recentRows` and `frecency`. They replace pick memory (`pickMemory`, removed).

**Frecency store.** `src/frecency.js`. `localStorage` key `burrow:frecency:<graph name>`, this browser only, a JSON array of `{ k, id, s, t }`: `k` is `"block"` or `"page"`, `id` the block or page uid, `s` the score, `t` the time of the last pick in ms. Nothing else is stored (no block text, no query, no alias): the loader rebuilds each entry from those four fields. A pick sets `s = s * 0.5 ** ((now - t) / 14 days) + 1` and `t = now`. At most 500 entries; past that the least recently picked go. `scores(kind)` is one `Map` uid → score made when first asked after a change (the scores are `s` decayed to that moment; the order between entries does not change with time), so the keystroke reads a ready Map. `recent(kind, n)` is cached the same way. `clear()` empties the store and removes the key; `reload()` re-reads the stored value (the live gate puts the browser's own value back and syncs the instance).

**Migration.** The first time 0.8.1 loads, `burrow:picks:<graph>` (`{ kind: "ref" | "alias", q, uid, t }`, alias uid `pageUid:alias`) is folded in: `ref` → block, `alias` → page (the part before the first `:`), one pick per old pick at its own `t`, in time order; `q` and the alias text are dropped; the old key is then removed. A broken old value is just removed.

**Ranking.** The score is a tie-break, never a promotion. In `((` (`rankRefs`, option `frequent`) it comes right after the ref step: match band, originals before quoters, long after short, `log2` ref step, **frequent**, alias hit, on the page being edited, title match, score, length, uid. In `[[` alias rows (`matchAliases`, option `picked`, keyed by page uid) it comes after the match score and before the title. It applies at any query length and needs `frecency` on.

**What a pick records.** In `commit()`, with `frecency` or `recentRows` on: an insertion that is a `((uid))` records that block; an alias, page or drill row without one records its page. Roam's own rows count too: when Burrow holds no row (ARMED) and plain Enter or Tab, or a mousedown on one of Roam's rows (`.rm-autocomplete__results-scroll > div`), picks, the strip remembers the textarea and token start, and on the next input event or two frames later reads the text at the token: `((` + 9 characters + `))` records that block, `[[Title]]` records the page that `indexes.titles.resolve(Title)` gives. A few string operations, no query; once per remembered pick; nothing is recorded when the text there is neither.

**Recent rows.** Shown with `token.query.length <= 2` (not in drill, not in `[[` right after `#`). Candidates: the 10 latest picks of the kind (blocks in `((`, pages in `[[`), then the latest edits, deduped by uid, without the block being edited (`st.uid`) and, for pages, the page being edited (`st.pageTitle`). With nothing typed the first three show; with one or two characters, the candidates with a word that starts with them (`searchKey` tokens, worked out once per uid and text). A `((` row is a `ref` row (`recent: "pick" | "edit"`, insertion `((uid))`, the count of references from the ref index, not shown when 0). A `[[` row is the new kind `page` (`uid`, `title`, `recent`, insertion `[[Title]]`, `refs` from the alias index's page counts or `null`). In `[[` they come after the alias rows, deduped against them and, in `visibleRows`, against the titles in Roam's own rows (the placeholder rows "Search for a Page" and "Search for a Block" are not pages), so up to six are made and three shown. **Nothing is pre-selected** (`render()`: `wanted` is false when the first row is recent), so Enter stays Roam's; ↑ from Roam's first row, which at an empty `((` or `[[` is the placeholder (checked live in notes, 2026-10-27), moves onto the last Burrow row as for any row. The kind `page` works like an alias row without chips: preview (Ctrl-O), Tab drills into its page, ⌥A adds an alias, hint line `↵ insert · ⇥ blocks on this page`, tip `Recent pick` / `Edited recently`.

**Data, all off the keystroke path.** (1) Recently edited, in the idle build (`src/indexes.js`, only inside the quiet rule: no key or click within 2 s, no popup): `[:find ?u ?t ?pu ?pt :in $ ?since :where [?b :edit/time ?t] [(> ?t ?since)] [?b :block/uid ?u] [?b :block/page ?p] [?p :block/uid ?pu] [?p :node/title ?pt]]` with `since` 14 days back. Measured 2026-10-27 in notes (105k blocks, 4,006 edits in 14 days): 274 ms the first time, then 183–188 ms, on the main thread, hence the quiet idle slot (the first build too; a build that is not quiet keeps the last list). From the rows, `latestEdits` keeps the 30 newest blocks and the 20 pages whose newest block is newest, in one pass; the strings of the blocks come from one `pull_many` (a pull each without it), empty ones dropped, 20 kept: `indexes.recent = { blocks: [{ uid, string, page, t }], pages: [{ uid, title, t }], builtAt }`, in memory only. (2) Recent picks: a picked block found in the ref index or `indexes.recent` needs no read; any other is pulled once at idle (`[:block/string {:block/page [:node/title]}]`) right after the pick and after each build, kept in memory, and skipped when the pull returns nothing (deleted). Pages take their title from `indexes.titles.byUid(uid)`.

**Per key.** `rank()` → `mainRows` as before, then `recentRows`: `frecency.recent()` (cached array), 10 + 30 candidates merged, a word-start test on cached tokens, at most six rows built. 0 queries, 0 pulls; the perf gate's `((` opener and first two typed characters are these keys.

**Forget.** The command palette entry `Burrow: forget recent picks` (also `window.__BURROW.forgetPicks()` for the gates) clears the store and the in-memory pick rows. `Disable all features` turns `recentRows` and `frecency` off.

## 19. Query filters (BRW-18)

Precedents: RefX R5 filters, Omnisearch (phrases, `-` exclusions, `path:`), Search+ (page scopes), Logseq's search in page (BRW-12 §2, §4). Switch `queryFilters`, on.

**Grammar** (`src/filters.js`, `parseFilters`, pure). The token is read, never rewritten.
- `"words"`: a phrase. Its words must stand together in order, each a whole word (`hasRun` over the key's tokens); with no closing quote yet the last word may be a prefix. The phrase's words also join the scorer's plan, so they rank as before.
- `-word`, `-"two words"`: excluded. Only `-` at a word start followed by a letter or a quote: `ant-man`, `a - b` and `-20` stay text.
- `in:here`: the page being edited (`st.pageTitle`, the edited block's `[data-page-title]`). `in:Title`: runs to the next filter (`in:` `ns:` `is:` `"` `-x`) or the end, so a title with spaces needs no quotes; `in:"Title"` ends at its quote. Resolved with the drill's title index (exact, case, separators, alias); a value that names no page is compared as typed.
- `ns:A/B/`: the page `A/B` and pages under `A/B/` (trailing `/` optional). One word, like `in:here`; `ns:"A B/"` for a namespace with a space. So `((in:here pcr` and `((ns:Systems/ grok` search `pcr` and `grok`.
- A named filter needs its value right after the colon (or the colon at the end, while typing): `what it is: foo` is text.
- `is:todo`, `is:done`: the block's first task macro (`taskParts`, the checkbox reader: `{{[[TODO]]}}`, `{{TODO}}`, `{{[[DONE]]}}`, Better Tasks' `{{[[DONE]]:((uid))}}`; a SmartBlock button that starts like one is no task). A prefix names its state while typed (`is:t`); another value matches nothing.
- Any other word is search text. A filter needs its colon, quotes or `-`. `in:` with nothing after it is taken out of the text and filters nothing yet, so typing `in:` does not change the rows.
- Page filters (`in:here`, `in:`, `ns:`) add up: a block passes when any names its page. Every other filter must hold.

**Where it applies.**
- `((`: `rankRefs` takes `accept`, tested on the row's block after a quoter folds into its original (the page that counts is the original's). Phrases and exclusions read the prose key, and the code key when code is matched (`looksLikeCode` of the search words, or `refProse` off). The pool stays the referenced blocks (§3): the gate page `PhD/Cronobacter & Spore Control in PIF` has 20 blocks with `pcr`, 6 of them referenced; Roam's list has the rest. Reading a page's other blocks would be a pull of up to 28,570 blocks (377 ms on that page, §5), not a per-key cost.
- `[[`: alias rows through `matchAliases`' `skip`. Phrases and exclusions read the alias and the title; `in:`/`ns:` test the row's page title; `is:` leaves no page row.
- Drill (`[[Page#h > x`) parses first and is unchanged.
- Search words without filters go to the plan, the code test and highlighting; filter values are never highlighted. roam-aliases' fold-in keeps the raw query (roam-aliases filters on what is typed).

**Label line.** With rows and at least one filter, `div.burrow-filters` is the strip's first child: the filters as typed joined by ` · `, `in:here` with its page in parentheses, 11 px at 0.6 opacity like the context line, 18 px counted in the strip's height. Not a `.burrow-row`, so keyboard indexes are unchanged. No match leaves no rows and so no line.

**Cost.** One regex decides that a query holds no filter; with filters, the parse is a single pass over the token and the tests run only on blocks that already matched (the prefilter cache is keyed on the plan's words, unchanged).

**Gates (0.9.0).** svy: 18 `filters:` cases (fixture: `is:todo`, `is:done`, `-closed`, `"quilt pattern"` vs `quilt pattern`, `in:`, `in:here`, `ns:`, no-match `ns:` and `in:`, the switch off, two `[[` cases; real data: `((watch is:todo` only open TODOs, `(("black panther"` only rows where the words stand together, `((black panther`; Escape and Enter on `((zebra task is:todo` byte-for-byte in the on, off and gone arms) all PASS. notes: 9 cases including `((pcr in:PhD/Cronobacter & Spore Control in PIF` (every row on that page) PASS. `perf-gate --filters`: svy p95 2.0–2.1 ms per key, notes 1.6–1.7 ms (budget 4). Screenshots: `tools/shots.mjs` 63–65, both graphs, light and dark. After merging 0.8.1 (recent rows, frecency) the key cases ran again on the merged build: svy 7/7 (with 0.8.1's recent-rows byte case), notes 3/3, three-filter p95 svy 2.1–2.3 ms, notes 1.6–1.8 ms.

## 20. Alias polish (BRW-19)

Two switches, both on: `aliasUsage` and `aliasPrefix`. `Disable all features` turns both off.

**Use count.** Per alias page, the number of `[alias]([[Page]])` links in the graph. In the idle build (`src/indexes.js` `build()`, beside the reference counts, same alias page uids, only with `aliasUsage` on): `[:find ?u ?r ?s :in $ [?u ...] :where [?p :block/uid ?u] [?r :block/refs ?p] [?r :block/string ?s] [(clojure.string/includes? ?s "]([[")]]`. `?r` is in `:find` so equal strings in different blocks are not collapsed. It is its own query because the reference-count query (`ALIAS_REFS`, `(count ?r)`) returns only a number per page and the alias text is in the strings. Measured read-only 2026-10-27: 56 ms async for 8 alias pages in notes (0 alias links), 73–76 ms for 24 alias pages and 29 linking blocks in svy, beside 59 ms for `ALIAS_REFS` there; timed as `perf.push("aliasUses", ms)`. `countAliasUses(index, rows)` (`src/aliases.js`, pure) matches every `/\[([^\[\]]+)\]\(\[\[([^\]]+)\]\]\)/g` in each string, and counts it for the row's page uid when the link title equals that page's title exactly and the text, trimmed and lowercased, is one of that page's aliases. Two links in one block count twice; links to other titles, non-alias text and plain `[x](url)` do not count. The result is a Map keyed `pageUid\u0000aliasLower`.

**Where it lives.** `setAliasUses(index, uses)` stores `index.usesByAlias` (that Map, at `window.__BURROW.indexes.aliases.usesByAlias`) and precomputes `index.aliasesByUse`: page uid → the page's aliases, most used first, ties in the alias block's order (a stable sort of `pageAliases`). `aliasUses(index, uid, alias)` is the lookup for a tip. `swapAliases` (an alias edit) carries the counts to the new index with `setAliasUses(next, aliases.usesByAlias)`, as `refsByPage` is carried; a new alias has none until the next build. Turning `aliasUsage` on while no count was read (`indexes.usesRead` false) schedules a build.

**Per key.** `groupAliasHits(hits, index, { byUse })` takes `aliasesByUse.get(uid)` when `byUse` (the setting) and the list exists, else `pageAliases`. A chip's `title` and the hover tip's heading are `<alias>` or `<alias> ×N` (N > 0, switch on), from one Map lookup. `chipRow` and `chipKey` read `row.aliases`, so keys follow the new order: ⌥↓ enters on `row.aliases.indexOf(row.alias)`, ←/→ move, Enter inserts that chip. `foldedByRow` tests membership in `row.aliases`, which reordering does not change, so no alias shows twice (Burrow row and roam-aliases item). No query, no pull.

**Shared aliases.** An alias on two pages gives two rows, never merged and never guessed: `groupAliasHits` dedups by page uid, not by alias text, and with `aliasInline` off the keys are `alias:<uid>:<alias>`; each row carries its own `refs`, and its chips its own use counts. Checked in `groupAliasHits`, `matchAliases`, `visibleRows` and `foldedByRow`; nothing needed fixing.

**`alias:` prefix.** In `rank()`, before drill and recent rows: a `[[` token (not right after `#`) whose query matches `/^alias:\s*(.*)$/is`, with `aliasPrefix` and `aliasPages` on, is in prefix mode; `st.aliasOnly` holds the rest (else `null`, reset each `rank()`). An empty rest (after trim) gives no rows. Otherwise `mainRows` ranks aliases for the rest alone, with no minimum length (one character works), the usual `matchAliases` / `groupAliasHits` / `aliasInsertion`, so Enter inserts `[alias]([[Page]])` or `[[Page]]`; `applyToken` replaces from the token start through the closer, so `alias:` does not survive. No recent rows, page rows or drill for the token. `visibleRows` in prefix mode only slices to `ROW_LIMIT`: no filtering against Roam's titles or roam-aliases (roam-aliases searches the literal `alias:lo` and lists nothing, so nothing can repeat). Pre-select: the usual `aliasPreselect` rule on the rest, `aliasStarts(rows[0].alias, rest) && !exactTitle(rest)`. Highlight uses the rest too. One regex on the query per key.

**Data note.** In notes (checked read-only 2026-10-27) there are 8 alias pages, none with three or more aliases, and 0 `[alias]([[Page]])` links, so the live gate builds a scratch fixture page for the order.

## 21. Tables in the preview (BRW-20)

Precedent: BRW-12 §3 ("Roam Grid tables in the picker"), Roam's native table, Roam Grid (`~/roam-grid`, `tableCells`). Switch `previewTables`, on.

**What is drawn.** In any of Burrow's preview panes (drill-down, the row preview, the Tab list's preview), when the highlighted block matches `{{[[table]]}}` or `{{table}}` (case and spaces ignored, anywhere in the string; `src/table.js` `isTableBlock`), `previewModel` puts one table item where the target's child outline would go. The pane draws it as `div.burrow-table` (CSS grid, `--burrow-cols`) of `div.burrow-cell`s, 6 rows x 5 columns at most, rectangular (a short row is padded with empty cells), then `div.burrow-table-more` with `+R rows`, `+C cols` or both when the table is bigger. The column count comes from the chain pull (5 levels with text, then ids to a recursion limit of 30), so it is exact up to 36 columns; a wider table shows `+31 cols`. A cell is cut at 40 characters with `…` (`clipParts` over rich parts, or the plain string) and drawn with the rich parser when Rows drawn like Roam is on. `" "` (Roam Grid's stored empty cell) is empty; a formula is its text. `{{[[roam/grid]]}}` does not match, so a large grid keeps its rich label. Text nodes only, no handlers, no `on*` attributes, no Roam Grid code and no `window.roamGrid` call.

**Storage read.** Rows are the table block's children by `:block/order`; a row's cells are the row block and then, level by level, the child with the smallest order (Roam Grid's first-child chain). `src/pagetree.js` `table(uid)` exists on the full reader (drill, Tab list) and the bounded one (row preview):
- Row ids: the children already known as nodes when the drill read them, else the preview's paged id read (`SLOTS`, then `KID_IDS` and orders 150 at a time past 150 children).
- One `CHAIN` pull per shown row: five levels with uid, string and order, then ids and orders only with recursion limited to 30 levels to count the columns past the fifth. Measured on notes' tables: 0.1–2.8 ms per whole-table pull; one row's chain is a fraction of that.
- Through the bounded reader's guard, so a used-up slice throws `PAUSE` between rows and the next slice resumes without pulling a cached chain again. Counted as `tableChains` in `__BURROW_PERF.counters`. Model and chains are kept by uid until the popup closes (`tree.clear()`).

**Drawn at idle.** A key's draw (`show`/`fill`) never writes the table line: `writeLines` stops at it and leaves it to `more()`, which the preview's idle slices already run. A drill that flips between a section and its table on every key (`perf-gate --table`) rebuilt 30 cells per key and measured 5.4 ms p95 per key in svy before this. The drill and Tab-list models are rebuilt when the switch flips; the row preview takes it at the next row.

**Gates (0.9.2).** svy live gate 105/105 and notes (light) 101/101 PASS, including the four `table:` drill cases (grid content, Escape and Enter byte-for-byte across arms, switch off, 6 chain pulls for the 200-row fixture). `tools/grid-gate.mjs` PASS in svy: Roam Grid's arrows move its active cell before and after the popup, and the table and its metadata are unchanged. The fixture's table sections are created collapsed, so their ~470 blocks are not rendered in the gate's sidebar. Per-key performance gates were dropped at Svy's request.
